## 1. 这份草案要解决什么

当前项目功能已经可用，但“项目列表”和“项目门户”之间缺少统一的状态入口：列表只告诉用户项目名称，工作台把菜单、原型预览、轻协作任务、成员和快照集中在一个页面。阶段 22.1 先冻结信息架构和交互语义，避免在 `ProjectView.vue` 继续叠加局部状态；用户确认后，才拆组件、补聚合接口和做真实页面验收。

本阶段不改变轻协作默认路线，不重新启用 BL-002 GitLab Provider，不新增下载/编辑/上传/删除权限，也不把项目字段直接扩展到 Skill 或 MCP 契约。

### 2.1 当前首屏请求和性能风险

- 项目列表首屏是一次 `GET /projects`，但响应不带分页和摘要字段；项目规模增大时只能把全部可见项目拉到浏览器。
- 项目工作台挂载时并行触发 `GET /projects/:id` 和原型列表请求；切换菜单项后，再触发一次 `GET /projects/:id/changes?prototypeId=...`。
- 当前详情接口已经将绑定原型、签出状态、成员和角色聚合返回，阶段 22.1 不应为了拆组件重新制造逐项请求。
- 原型绑定选择器应改为服务端关键字搜索/分页；不得以“前端一次性加载全部原型”作为长期方案。

## 3. 角色与核心任务

角色沿用现有权限模型，下面的“任务”是信息架构假设，待用户确认优先级：

| 角色 | 首要问题 | 应看到的主动作 |
|---|---|---|
| 平台管理员 | 找到任意项目和原型，判断是否需要介入 | 搜索/筛选、只读查看、审计入口；项目变更动作仍按项目权限控制 |
| 项目负责人（owner） | 知道项目是否可交付、哪些候选待采用 | 进入工作台、处理待确认候选、管理绑定/成员/快照 |
| 项目管理员（admin） | 协助负责人维护项目 | 管理菜单、绑定、成员和快照；保留后端授权 |
| 编辑者（editor） | 领取任务并提交候选，不误改正式版本 | 查看正式预览、创建/编辑任务、查看候选状态 |
| 查看者（viewer） | 快速查看当前正式原型 | 只读菜单和预览，不显示会返回 403 的管理动作 |

## 4. 建议的信息架构

```text
项目
├─ 项目列表 /projects
│  ├─ 搜索 + 范围筛选（我负责 / 我参与 / 有待处理）
│  ├─ 项目状态摘要（绑定原型、待确认候选、最近活动）
│  └─ 项目卡片/表格 → 进入工作台
└─ 项目工作台 /project/:id?prototypeId=&menuPath=
   ├─ 工作台头部：项目名、角色、整体状态、全屏预览、更多管理
   ├─ 项目导航：菜单树、绑定状态、签出状态
   ├─ 当前工作区：正式版本预览 / 未绑定引导 / 预览不可用
   └─ 上下文抽屉
      ├─ 任务与候选时间线：创建→领取→上传→校验→待确认→采用/退回/失效
      ├─ 成员与权限
      └─ 快照与恢复
```

### 4.1 项目列表低保真

```text
┌ 项目 ───────────────────────────────────────────────┐
│ 按业务系统组织原型                         [创建项目] │
│ [搜索项目……] [我负责⌄] [状态⌄] [有待处理] [刷新]     │
│                                                     │
│ ┌ 项目名称 ───────┐ ┌ 项目名称 ───────┐             │
│ │ 状态/角色       │ │ 状态/角色       │             │
│ │ 原型 3 · 待确认 2│ │ 原型 0 · 无待办  │             │
│ │ 最近活动：……     │ │ 最近活动：……     │             │
│ │ [进入工作台] ⋯   │ │ [进入工作台] ⋯   │             │
│ └─────────────────┘ └─────────────────┘             │
│ 空数据：没有符合条件的项目 → [创建项目]              │
└─────────────────────────────────────────────────────┘
```

列表卡片只保留能帮助排序和决策的摘要：角色、绑定原型数、待确认候选数、最近活动时间/类型。成员总数可作为次要信息；不在没有消费场景时堆叠 DAU、访问次数等指标。

### 4.2 项目工作台低保真

```text
┌ ← 项目名                         [角色] [全屏预览] ⋯ ┐
│ 描述 · 状态摘要：3 个原型 / 2 个待确认 / 最近活动…  │
├───────────────┬──────────────────────────┬──────────┤
│ 项目导航       │ 当前工作区               │ 上下文     │
│ ▾ 业务模块     │ [正式 v1.4] [任务管理]    │ 待确认 2   │
│  · 客户列表 ✓  │                          │ 最近活动   │
│  · 订单管理 ⚠  │   ┌────────────────┐     │ 时间线     │
│ ▾ 系统设置     │   │  原型预览       │     │           │
│  · 用户权限 ○  │   │                │     │ [成员]     │
│                 │   └────────────────┘     │ [快照]     │
│ [绑定/排序]     │ [让 AI 修改] [原型详情]  │           │
└───────────────┴──────────────────────────┴──────────┘
```

- 左侧是稳定的项目结构；点击菜单只改变当前工作区，不把任务/成员/快照变成第二套导航。
- 中间只承载“当前正式版本”和当前动作；未绑定时显示绑定引导，预览失败时显示原因与重试。
- 右侧上下文默认收起为摘要，点击后以抽屉/弹层展开，降低首屏认知负担。
- 深链接保留 `projectId`、`prototypeId`、`menuPath`，刷新或从项目列表返回时能够恢复定位。

## 5. 关键交互和状态

| 状态 | 页面反馈 | 可执行动作 |
|---|---|---|
| 首次加载 | 列表/工作区骨架屏，避免空白闪烁 | 取消或重试 |
| 无项目/无菜单 | 说明原因和下一步，不只显示“暂无数据” | 创建项目/管理菜单 |
| 菜单未绑定 | 显示目标菜单路径与权限提示 | owner/admin 使用搜索分页选择原型 |
| 原型无入口或预览失败 | 显示版本、入口文件和失败原因 | 重试/打开原型详情；不自动改正式版本 |
| 有待确认候选 | 头部和当前原型同时显示数量 | 打开时间线，预览后采用/退回 |
| 候选过期/校验失败 | 使用“已过期/预览失败”语义，不与“待确认”混用 | 查看原因、重新发起任务 |
| 签出中 | 在菜单项和工作区显示持有人及剩余时间 | 本人签入；owner/admin 按权限强制释放 |
| 无权限/会话过期 | 403 与 401 分开提示，管理按钮不提前展示 | 返回项目列表/重新登录 |
| 快照为空或恢复风险 | 在操作前说明会影响的菜单/绑定 | 二次确认后创建/恢复/删除 |

## 6. 实现候选（本阶段不编码）

1. **拆前端职责**：将 `ProjectView.vue` 拆为 `ProjectHeader`、`ProjectNavigation`、`ProjectWorkspace`、`ProjectChangeDrawer`、`ProjectMembersDrawer`、`ProjectSnapshotsDrawer`、`PrototypeBindingPicker`，由页面只负责路由和数据编排。
2. **列表聚合**：`GET /projects` 增加可选 `scope`、`status`、`page`、`pageSize`，返回 `items`、`total` 和摘要字段；保持旧 `data` 读取兼容，先由前端适配层切换。
3. **绑定选择器**：增加按名称/创建者/版本的服务端搜索和分页，明确管理员是否可见全部有效原型；不能依赖 `getPrototypes({})` 的默认个人范围。
4. **工作台聚合**：保持 `GET /projects/:id` 一次返回项目上下文，候选时间线按当前原型按需加载；记录请求数量和关键接口耗时，避免逐卡片/逐成员 N+1。
5. **状态词典**：前后端共用任务、候选、签出、预览和权限状态的显示映射，错误码保留机器可读值。
6. **可访问性**：菜单树、抽屉、预览 iframe、状态标签提供键盘焦点、可读名称和非颜色提示；不以色彩作为唯一状态信息。
