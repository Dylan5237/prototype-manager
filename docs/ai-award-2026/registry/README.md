# 结构化台账说明

本目录保存统计期内用于计算评优指标的结构化台账模板。仓库为公开仓库，真实数据落盘前必须先判断是否包含个人信息或敏感业务信息；必要时只提交脱敏 ID、聚合值或证据索引，原始明细保存在公司内部受控位置。

## 文件

### `target-users.csv`

用于冻结“目标用户”分母。核心字段：脱敏用户标识、部门/业务单元、岗位、为什么属于目标用户、有效期间和状态。

目标用户按实际服务岗位确定，不得使用部门总人数直接充当分母，也不得在统计结束后为了评分倒推调整。

### `weekly-metrics.csv`

每周固定记录目标用户、有效用户、覆盖率、有效任务、重复使用、部门数量、准确性/效率样本、节时率、案例与录屏进度。历史行只追加；如修正数据，在 notes 中说明并同步决策/周报。

### `evidence-register.csv`

所有关键证据的总索引。证据类型建议使用：

- CASE
- EFF
- ACC
- CROSS
- FLOW
- FEEDBACK
- DEMO

`source_location` 可以是公司内部受控文件位置、平台任务/日志标识、GitHub 文档路径等。禁止在公开仓库填写密码、token 或敏感个人信息。

## 有效使用统计原则

建议冻结口径：一个真实业务需求，通过伏羲完成一次可被验收的原型创建或修改任务，并在平台形成可追溯结果，计为一次有效使用。

同一业务任务中的 Agent 重试、底层多次调用、页面刷新不能重复累计。
