## 5. 日志与可追溯性

正式证据应证明：

- 用户/任务/原型/版本能够关联；
- 统计期有效任务能够去重；
- 成功/失败及必要业务结果可追踪；
- 代表案例能够回到真实任务记录；
- 不依赖人工回忆填写最终数据。

## 6. 反馈闭环

建议将以下链路作为持续优化证据：

`用户反馈/真实失败 → Issue/任务 → 修复或文档改进 → release/内容发布 → 验收 → 后续反馈`

正式提交时选择 2～3 个最典型、可公开/可脱敏的闭环案例，不需要把所有研发 Issue 都交给评委。

## 7. 持续更新

建议保留：

- release 记录；
- Help Center 更新记录；
- 关键功能/可靠性问题修复记录；
- 用户反馈后的产品改进；
- 周度统计和复盘。
