# 2026 AI 赋能工具评优｜伏羲申报档案库

本目录是伏羲平台参加公司《2026 年度 AI 赋能工具评优活动》的完整申报档案库。它不仅保存最终申报稿，还持续保存官方规则、申报策略、统计口径、真实使用证据、代表案例、周度数据、跨部门证明、演示材料和决策记录，使最终申报中的每个关键数字与结论都可追溯。

## 当前策略

伏羲平台符合申报范围，采用“双轨策略”：

- **主攻：专业场景提效奖**。当前优势集中在专业任务提效、准确可靠和流程规范化，与该奖项“效率与效果 40%”的权重结构高度匹配。
- **条件满足后同时申报：AI 赋能综合示范奖**。Gate：统计期内至少两个相互独立部门或业务单元完成真实使用验证，并具备联系人、用户、任务和结果证明。

建议申报定位：

> **伏羲平台——AI 驱动的原型生产与协作工具**
>
> 将“需求描述 → AI 原型生成 → 修改迭代 → 人工审核 → 版本沉淀 → 分享评审”形成统一闭环。

## 档案结构

### 控制文档

- `00-archive-governance.md`：档案治理、真实性和版本规则
- `01-source-summary.md`：官方通知关键规则摘要
- `02-positioning-and-feasibility.md`：伏羲申报定位与可行性分析
- `03-metrics-and-data-plan.md`：统计期指标、数据口径与冲奖目标
- `04-evidence-and-execution-plan.md`：证据链、案例、录屏与阶段执行计划

### 原始来源 `source/`

- `README.md`：来源索引与原始文件管理规则
- `2026-ai-award-notice-transcription.md`：官方通知的结构化转录，保留原始 PDF SHA-256；公开仓库不复制个人联系电话/邮箱

### 结构化台账 `registry/`

- `target-users.csv`：目标用户清单模板
- `weekly-metrics.csv`：周度指标快照
- `evidence-register.csv`：所有证据统一登记索引

### 代表案例 `cases/`

- `CASE-TEMPLATE.md`：一案例一档，连接真实需求、任务结果、准确性、效率和录屏证据
- 后续正式案例按 `CASE-001`、`CASE-002`…归档

### 证据 `evidence/`

- `efficiency-comparison.csv`：不少于 10 组同类任务前后耗时与质量对比
- `accuracy-review.csv`：不少于 10 个代表案例的统一准确性复核
- `CROSS-DEPARTMENT-TEMPLATE.md`：综合示范奖跨部门真实使用证明模板
- 后续补充流程治理、用户反馈、截图/录屏索引等材料

### 周度档案 `weekly/`

- `WEEKLY-TEMPLATE.md`：统计期每周数据快照、评分趋势、异常和下周动作
- 周报只追加，不覆盖历史数据

### 最终申报 `submission/`

- `application-draft.md`：正式申报工作稿；所有统计数据保持占位直到真实数据形成
- 后续补充最终报名表、正式材料目录、10 个案例录屏脚本和现场问答材料

### 决策记录 `decisions/`

- `decision-log.md`：奖项策略、申报定位、有效使用口径、效率口径等重要决策

## 当前必须在 9 月 15 日前冻结的事项

1. 目标用户定义与目标用户清单；
2. “一次有效使用”的正式统计口径；
3. 使用频率的目标值/达成率口径；
4. 传统人工基准耗时的测量方法；
5. 伏羲总耗时中人工复核、返工和等待时间如何计入；
6. 准确性统一验收规则；
7. “严重错误”的定义；
8. 数据日志是否足以还原用户、部门、任务、时间和最终结果；
9. 首批真实使用人员和每周数据复核责任人。

## 工作原则

1. 只统计真实业务任务，不把内部测试、重复刷新、无效调用或批量造数计入有效使用。
2. 目标用户按实际服务岗位界定，不以部门总人数扩大分母。
3. 以平台真实日志、任务记录、案例、用户反馈和前后耗时对比作为证据。
4. 原始证据与分析结论分开保存；修正数据必须留下原因和时间。
5. 申报材料面向评委解释“业务价值”，不把 MCP、Task v2、Harness 等内部技术名词作为主叙事。
6. 统计期开始前冻结核心口径；统计期内如必须变更，在 `decisions/decision-log.md` 追加记录。
7. 该 GitHub 仓库为公开仓库，不提交 token、密码、用户隐私、内部敏感业务数据和未经脱敏的私有证据；必要时只保存证据编号、校验值和内部存储位置。
