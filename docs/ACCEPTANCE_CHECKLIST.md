## 先读：环境与证据边界

- **16077 是测试环境**：本清单中标为“可在 16077”的项目应在 `http://192.168.2.145:16077` 执行；不需要、也不授权发布到 16088。执行前先确认登录后页面显示的是测试环境，记录当前 release/时间。
- **16088 是生产环境**：本清单不能作为生产发布授权。即使 16077 通过，16088 仍需独立的构建、备份、发布确认和业务验收。
- **只使用隔离测试数据**：写入测试使用新建且名称含 `[ACCEPTANCE]` 的项目/原型、专用测试账号和测试 ZIP；不覆盖已有业务原型、不删除既有数据、不把生产数据作为候选采用目标。
- **建议证据位置**：在本次验收记录中写入 `docs/acceptance-evidence/YYYY-MM-DD/<编号>/` 的实际路径或外部工单链接；至少保留截图、执行时间、账号角色、项目/原型 ID、结果和失败信息。该目录按实际执行时创建，本清单不代表其中已有证据。

## 阶段 22：项目模块

### 22-01 项目列表、筛选与默认入口（可在 16077 完成）

- [ ] **前置条件**：使用 owner 或 admin 登录 16077；存在至少两个隔离项目，其中一个有多个已绑定菜单。
- **操作步骤**：打开“项目”；分别使用“我负责/我参与/有待处理”筛选和关键字查询；进入有绑定菜单的项目；刷新页面；再使用有效 `projectId`、`prototypeId`、`menuPath` 深链接进入。
- **预期结果**：列表显示绑定原型数、成员数、待确认候选数和最近活动；筛选结果与账号关系一致；普通进入时打开菜单配置顺序中的第一个已绑定菜单；有效深链接优先且定位正确。
- **备注/证据位置**：记录筛选条件、项目 ID、进入前后 URL、列表和工作台截图；`docs/acceptance-evidence/YYYY-MM-DD/22-01/`。

### 22-02 四角色可见性与后端拒绝（可在 16077 完成；需四个角色账号）

- [ ] **前置条件**：同一隔离项目已配置 owner、admin、editor、viewer；测试者能分别登录四个账号。
- **操作步骤**：依次登录四个账号，打开同一项目的绑定、任务/候选、成员、快照区域；记录可见按钮；对 viewer 和无关账号尝试一个管理 URL/API 操作（不执行破坏性写入）。
- **预期结果**：各角色只看到自己允许的动作；viewer 不显示管理动作；越权请求由后端稳定拒绝（例如 403），前端隐藏不替代后端权限检查。
- **备注/证据位置**：记录账号角色、页面截图、请求状态和响应摘要；`docs/acceptance-evidence/YYYY-MM-DD/22-02/`。

### 22-03 绑定原型搜索、分页与预览失败反馈（可在 16077 完成；需多条有效原型）

- [ ] **前置条件**：隔离账号下准备足够多的有效原型，至少有一条可按名称搜索到；准备一条无入口或不可预览的测试原型（如环境不允许，记录“未准备”）。
- **操作步骤**：在绑定选择器输入名称/创建者关键词，翻页并选择目标原型；打开预览；再打开不可预览样本。
- **预期结果**：搜索和分页在服务端生效，不一次性加载全量原型；正常原型可预览；异常样本显示可理解的失败原因和重试/详情入口，不自动改写正式版本。
- **备注/证据位置**：保存网络请求、页码、目标原型 ID、正常/异常截图；`docs/acceptance-evidence/YYYY-MM-DD/22-03/`。

### 22-04 任务到候选审核、CAS 与退回（可在 16077 完成；需 owner/admin、editor 与两个候选）

- [ ] **前置条件**：使用一个 `[ACCEPTANCE]` 项目和原型；记录当前版本、入口文件、文件摘要和候选目录基线；准备两个基于同一版本的有效候选 ZIP。
- **操作步骤**：创建任务并由 editor 领取；分别上传两个候选；owner/admin 预览第一个并采用；尝试采用第二个；另创建一个候选并执行退回。
- **预期结果**：时间线完整展示创建、领取、上传、校验、审核和结果；采用后只产生约定的新版本；竞争候选不会静默覆盖，过期/冲突有明确原因；退回不改变当前版本、入口文件和文件摘要。
- **备注/证据位置**：记录任务码、候选 ID、前后版本/摘要、每步截图或 MCP/API 回读；`docs/acceptance-evidence/YYYY-MM-DD/22-04/`。

### 22-05 签出签入、成员和快照风险操作（可在 16077 完成；需权限账号）

- [ ] **前置条件**：隔离项目可进行签出、成员管理和快照操作；owner/admin 与 editor 账号均可登录；已记录操作前项目绑定和成员基线。
- **操作步骤**：editor 签出并签入一次；owner/admin 按权限尝试强制释放；添加/移除一个测试成员；创建快照，阅读恢复影响说明后恢复一次。
- **预期结果**：持有人和状态可见；只有授权角色可强制释放和管理成员；所有风险操作有二次确认与影响说明；快照恢复后的项目状态可回读且与预期一致。
- **备注/证据位置**：记录操作者、确认提示、快照 ID、操作前后状态；`docs/acceptance-evidence/YYYY-MM-DD/22-05/`。

### 22-06 管理员跨用户只读预览与审计（可在 16077 完成；需管理员和他人未分享样本）

- [ ] **前置条件**：准备“他人创建、未分享、已绑定项目”的有效原型；管理员账号与创建者账号分离；记录原型内容、版本和项目绑定。
- **操作步骤**：管理员从项目入口和原型列表分别打开该原型，查看详情、README/文件元数据和当前版本预览；检查相关审计事件；再以普通无关用户重复访问。
- **预期结果**：管理员只读访问成功；普通无关用户被拒绝；审计事件可回读且不含访问令牌；整个过程不改写内容、版本或项目绑定。
- **备注/证据位置**：记录原型/项目 ID、两类账号的结果、审计字段脱敏截图、前后版本对比；`docs/acceptance-evidence/YYYY-MM-DD/22-06/`。

## 阶段 23：Skill 质量与效率

### 23-01 三 profile 真实黄金样例（需 AI 客户端；可连 16077，但先在隔离目录构建）

- [ ] **前置条件**：准备同一真实业务题目及明确验收标准；AI 客户端已启用 `fuxi-prototype`；分别选择 `vue3-element-plus`、`vue3-skyui`、静态 HTML。
- **操作步骤**：用相同需求分别生成三个项目；保存实际提示词、选用 profile、生成结果和执行日志；在隔离目录构建每个项目并打开生产构建。
- **预期结果**：三个样例都能代表同一业务目标而非空壳页面；profile 与项目内容匹配；构建成功或给出可复现失败原因；不选择 SkyUI 的用例不读取/安装 SkyUI 专属能力。
- **备注/证据位置**：保存需求、profile、生成日志、构建输出和截图；`docs/acceptance-evidence/YYYY-MM-DD/23-01/`。

### 23-02 两种输出模式分别验收（需 AI 客户端与截图）

- [ ] **前置条件**：23-01 至少有一个可构建样例；明确本次是 `alignment` 还是 `implementation-proof`，不要混合评分。
- **操作步骤**：各选择一个样例，按对应模式生成并在生产构建中操作关键控件；截图检查布局、滚动、溢出、遮挡、空白区、不可达操作和缺失状态。
- **预期结果**：`alignment` 按视觉/布局验收；`implementation-proof` 的关键控件真实使用目标 runtime 组件并可操作；每种模式各有独立结论和问题清单。
- **备注/证据位置**：保存模式、视口、截图、操作录像/说明和问题列表；`docs/acceptance-evidence/YYYY-MM-DD/23-02/`。

### 23-03 生成—检查—修复闭环与质量门禁（本地可完成；真实样例必需）

- [ ] **前置条件**：有一个真实生成样例及其构建产物；保留初次运行状态；可运行 Skill 的质量门禁与 `validate_project -> pack_project -> validate_zip`。
- **操作步骤**：运行质量门禁；对发现的问题做一次修复；重新构建、重新截图、再次运行门禁；随后按顺序执行项目校验、打包和 ZIP 校验。
- **预期结果**：资源缺失、入口错误或 profile 冲突会明确 `FAIL`；缺少构建/视觉证据保持 `UNVERIFIED`，不会被手工改成通过；修复后有新的构建和截图；ZIP 是实际校验过的同一文件。
- **备注/证据位置**：保存两次门禁 JSON、修复摘要、构建/截图和 ZIP SHA-256；`docs/acceptance-evidence/YYYY-MM-DD/23-03/`。

### 23-04 项目任务到 `project-bound-update` 回读（需 AI 客户端、16077 和可写隔离原型）

- [ ] **前置条件**：16077 中有 `[ACCEPTANCE]` 项目、绑定原型和明确基础版本；AI 客户端实际指向 16077；记录目标 ID/版本/profile。
- **操作步骤**：从项目任务上下文发起更新；确认 Skill 解析出的 project/prototype/base version/profile；执行交付后回读原型版本和预览。
- **预期结果**：目标唯一时无需重复猜测；目标不唯一、版本不明或 profile 冲突时停止并请求确认；成功时目标 ID、基础版本、回读版本和预览一致。
- **备注/证据位置**：保存任务上下文脱敏副本、工具调用、回读和预览截图；`docs/acceptance-evidence/YYYY-MM-DD/23-04/`。

### 23-05 质量改善指标（需完成多个真实样例）

- [ ] **前置条件**：至少有与阶段 20 可比的真实样例数据；每例均记录首次质量结果和修复轮次。
- **操作步骤**：统计首次通过率、平均修复轮次、资源缺失数和预览失败数；与基线按同一 profile/模式/题目范围比较。
- **预期结果**：有可复核的改善，或如实记录未改善；不能仅因增加规则或样例而宣称质量优化完成。
- **备注/证据位置**：保存原始表格、计算方式和结论；`docs/acceptance-evidence/YYYY-MM-DD/23-05/`。

## 阶段 24：性能与稳定性

### 24-01 16077 只读基线复核（可在 16077 完成）

- [ ] **前置条件**：确认当前访问的是 16077；准备非敏感查询账号；不执行写入或发布。

- **预期结果**：每条链路都有 10 个可复核样本，可计算 p50、p95、最大值和失败数；异常能定位到具体调用而非笼统“慢/失败”。
- **备注/证据位置**：保存原始计时表和统计结果；`docs/acceptance-evidence/YYYY-MM-DD/24-01/`。

### 24-02 1/20/80 MB 真实上传与回读（可在 16077 完成；需大文件与可写隔离原型）

- [ ] **前置条件**：准备 SHA-256 已记录的 1 MB、20 MB、80 MB 有效 ZIP；使用 `[ACCEPTANCE]` 原型；记录上传前版本、入口文件和文件摘要。
- **操作步骤**：每档按已确认次数上传；每次完成后回读版本、入口文件、解压内容和预览；记录上传、服务端处理、回读与预览时间。
- **预期结果**：所有成功上传只生成预期版本；回读内容与 ZIP 一致；每档都能产出 p50、p95、最大值、失败数、内存/事件循环观测值（如可采集）。
- **备注/证据位置**：保存 ZIP SHA-256、每次时间、版本序列、回读与预览截图；`docs/acceptance-evidence/YYYY-MM-DD/24-02/`。

### 24-03 损坏 ZIP、重试幂等与无半成品（可在 16077 完成；需可写隔离原型）

- [ ] **前置条件**：准备损坏 ZIP；记录当前正式版本和文件摘要；如测试重试，使用同一幂等键和完全相同参数。
- **操作步骤**：上传损坏 ZIP；对一次可恢复网络失败按相同参数重试；再以改变参数的请求重试。
- **预期结果**：损坏 ZIP 被拒绝且不新增正式版本、不改变当前文件；相同参数的重试不产生重复版本；参数变化被识别为新请求并有明确结果。
- **备注/证据位置**：保存请求 ID/幂等键（脱敏）、状态码、前后版本和文件摘要；`docs/acceptance-evidence/YYYY-MM-DD/24-03/`。

### 24-04 MCP 接入、客户端发现与诊断（需 AI 客户端；可在 16077 完成）

- [ ] **前置条件**：独立 AI 客户端未复用生产配置；连接码、配置和临时凭据由当前会话获得且不写入仓库/文档。
- **操作步骤**：生成并兑换连接配置；首次启动 MCP；执行 `tools/list` 与 `check_connection`；重启客户端后再次发现工具；故意使用一次无效/过期配置。
- **预期结果**：正常链路能连接并发现预期工具；失败能区分兑换、安装、启动、发现或认证阶段；任何日志/证据不泄漏令牌。
- **备注/证据位置**：保存脱敏控制台日志、工具列表数量、阶段耗时和失败阶段；`docs/acceptance-evidence/YYYY-MM-DD/24-04/`。

### 24-05 Skill/MCP 更新与回滚一致性（需 AI 客户端；只在已授权测试制品上执行）

- [ ] **前置条件**：有明确的测试制品版本、previous/current 状态和回滚方案；操作目标是测试客户端，不是生产环境。
- **操作步骤**：检查 manifest；执行下载、SHA-256 校验、解压、Smoke、切换和 heartbeat；制造一次可控失败并回滚 previous 版本。
- **预期结果**：未变化制品不会无意义重复下载；失败后 current 指针、Skill 安装状态和 heartbeat 一致地回到 previous；摘要校验和原子切换未被绕过。
- **备注/证据位置**：记录旧/新版本、manifest/摘要、Smoke、heartbeat 和回滚结果；`docs/acceptance-evidence/YYYY-MM-DD/24-05/`。

- **预期结果**：不出现服务不可用、无响应或不可解释的数据错乱；资源峰值与事件循环延迟有实测记录，并与阶段 20/当前环境共同确定是否可接受；超过阈值如实判失败。
- **备注/证据位置**：保存并发数、监测曲线、错误日志、只读请求结果和阈值判断；`docs/acceptance-evidence/YYYY-MM-DD/24-06/`。
