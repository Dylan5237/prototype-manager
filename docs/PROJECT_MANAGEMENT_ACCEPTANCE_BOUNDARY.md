# 完整项目管理模块验收边界

> 基线日期：2026-09-07
>
> 目标：把伏羲项目模块从“菜单上的原型入口”升级为可分工、可执行、可审核、可追溯的项目工作空间。
>
> 当前状态：`in-progress`；任何单项代码、构建或 16077 health 通过均不代表本边界完成。

## 1. 产品边界

### 1.1 范围内

1. **项目结构**：项目可创建、编辑、归档；工作节点有稳定 ID，支持 1—3 级父子结构、排序、移动、停用和恢复。
2. **人员与分工**：owner/admin/editor/viewer 权限清晰；项目成员可被分配为节点负责人或参与者，节点负责人不是项目 owner 的显示别名。
3. **原型工作位**：叶子工作节点可绑定一个原型；绑定有独立 ID；绑定、迁移、解绑不依赖可变菜单路径保持关系。
4. **任务**：任务属于具体工作节点和当时的原型绑定；区分发起人、负责人、参与者和 Agent；可分派、领取、取消、完成和查询历史。
5. **候选与审核**：一个任务允许多次候选提交；每次提交有独立校验与审核记录；负责人显式采用后才生成正式版本；CAS 阻止过期候选覆盖。
6. **协作保护**：签出属于具体绑定；解绑、移动、成员移除、节点停用、快照恢复前检查活跃签出、未完成任务和待审候选。
7. **历史与审计**：重要变更形成可查询事件；取消不伪装成物理删除；快照记录稳定实体 ID、结构、绑定和版本。
8. **可用性与性能**：项目列表、工作台、任务管理器具备加载/空/失败/无权限状态；分页和聚合避免明显 N+1；桌面端关键路径可操作。

### 1.2 明确范围外

- 甘特图、工时、成本、预算、采购和财务核算。
- 即时聊天、邮件/短信通知和第三方 IM。
- 移动端专项视觉验收（仍按 BL-005）。
- GitLab 分支/MR 作为默认协作流程（BL-002 已取消）。
- 16088 生产发布；必须另行确认。

## 2. 核心实体合同

| 实体 | 必须成立的身份与关系 |
|---|---|
| Project | 稳定 ID；拥有成员、节点、快照和审计事件 |
| ProjectNode | 稳定 ID；属于一个项目；可有父节点；最多 3 级；区分 group/work |
| ProjectMembership | 连接 User 与 Project；保存项目角色和有效状态 |
| NodeAssignment | 连接 User 与 ProjectNode；区分 owner/contributor |
| PrototypeBinding | 连接叶子 ProjectNode 与 Prototype；一个有效节点最多一个有效绑定 |
| ProjectTask | 必须引用 node_id、binding_id、base_version_id；区分 requested_by 与负责人 |
| TaskAssignment | 连接 User 与 ProjectTask；保存负责人/参与者及接受状态 |
| AgentHandoff | 属于任务且签发给明确用户；短命、单次、最小 scopes |
| CandidateSubmission | 属于任务；每次提交独立编号、摘要、入口和状态 |
| Validation | 属于候选提交；允许多次校验并保留结果 |
| ReviewDecision | 属于候选提交；保存审核人、采用/退回和意见 |

| AuditEvent | 保存 actor/action/resource/result，不记录凭据和正文制品 |

## 4. 关键场景验收

### A. 结构与分工

- 创建含 1/2/3 级混合节点的项目；刷新后 ID、顺序和父子关系不变。
- 将陈雨设为“实体建模”负责人、赵明设为“方法建模”负责人；两人看到的节点和待办不同。
- 重命名或移动节点后，绑定、任务、候选和审计仍指向同一 node_id。

### B. 绑定与解绑

- 叶子节点可绑定原型，父节点被后端拒绝。
- 已绑定节点新增下级时，必须选择承接节点并原子迁移绑定。
- 无活跃协作时可解绑；原型和正式版本不删除，节点变为未绑定。
- 有 active 签出、editing/ready 任务或待审候选时解绑返回 409 和可行动原因；不得静默清理签出。

### C. 任务与候选

- 负责人创建任务并分派给成员；成员可用自己的身份领取并提交，发起人不必等于执行者。
- 一个任务连续提交两个候选，第一次失败/退回记录仍可查询。
- 采用候选生成正式版本并关联 review decision；竞争候选稳定变为 stale。
- 取消任务保留历史并撤销未使用交接，不显示为“已删除”。

### D. 权限与恢复

- 四类角色逐一走真实页面和 API；越权请求稳定 403。
- 快照恢复前展示影响清单；恢复后节点、分工、绑定和版本与快照一致，任务历史不被伪造或物理删除。

## 5. 非功能门禁

- 后端完整回归、前端测试与 build、MCP check/integration、Skill cache/行为回归、`git diff --check` 全部通过。
- 项目详情首次进入不得按节点产生 N+1；记录请求数及关键接口 p50/p95。
- 迁移在旧两级/三级 JSON 项目、重复绑定、活跃签出和未完成任务样本上可重复执行并可回滚。
- 16077 至少完成 owner/editor/viewer 三账号的真实闭环；API、页面、预览、数据库只读统计和审计事件相互一致。
