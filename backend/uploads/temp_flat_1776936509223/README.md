# 天宫开发平台 · 业务域版本管理与合并演示项目

本项目为"天宫开发平台"的**业务域设计**与**版本发布管理**模块提供了一套完整的前端交互原型，涵盖业务域建模、版本发布、BUG修复、外部依赖管理及可视化 JSON 业务域模型冲突检测与合并能力，以医疗信息化业务（门诊医嘱域）为例。

## 核心特性

### 1. 业务域设计（Domain Design）
- **多维度建模**：支持实体建模、方法建模、接口建模、物理建模、事件建模五大子页签切换。
- **业务模型切换**：顶部新增业务模型页签栏（医嘱信息、草药处方、皮试记录、检查申请、检验申请），支持多模型切换与关闭，替代原树状结构中的模型叶子节点。
- **版本与分支**：业务域信息栏展示当前域版本（如 `main-V1.3.7`）、分支切换器（main / bugfix），一键跳转"管理版本"。
- **状态管理**：实体/方法支持状态筛选（启用 / 未启用 / 作废）。
- **批量操作**：表格支持多选，底部提供"提交模型"、"新增"、"批量删除"等操作。

### 2. 版本发布管理（Version Release Management）
- **概览看板**：展示业务域的变更记录、外部依赖微服务、对外能力（API/页面/组件）、基础数据四大维度。
  - **版本隔离**：概览数据按版本隔离，版本切换下拉框内嵌在"概览"子页签顶部，选项带 `最新` / `历史` 标签。
- **发布记录**：维护 main / bugfix 分支的全局发布记录，支持"提交测试"。
- **BUG修复**：维护全局 BUG 列表，支持"新建 BUG"及可视化合并。

### 3. 语义级 Diff3 合并
- **三方深度对比**：基于 Base / Main / Hotfix 三方 JSON 进行递归对象/数组对比，按业务主键（`id`）匹配数组元素。
- **冲突精准定位**：自动识别"Main 修改 vs Hotfix 修改"的冲突点，并统计未解决的叶子冲突数。
- **双交互模式**：
  - **交互一（结构化对比）**：`MergeDialog.vue` 以业务卡片形式展示变更，左侧导航树高亮冲突/新增/修改。
  - **交互二（表单三栏对比）**：`MergeDialogMode2.vue` 以 Hotfix / Base / Main 三栏表单形式展示实体/方法字段级差异，底部提供逐字段裁决面板。
- **交互式裁决**：对冲突节点支持"采纳 Main"、"采纳 Hotfix"两种策略；无冲突节点自动合并，亦可手动覆盖。

### 4. 弹窗组件
- **提交测试**：选择分支（main / bugfix）、自动生成版本号、填写版本描述，选择需要发布的需求并查看其关联的数据对象变更记录。
- **新建 BUG**：支持多选 BUG 号，填写 BUG 描述，关联分支（main / bugfix）。
- **新建依赖**：为当前业务域添加外部依赖域，配置最小依赖版本与最大依赖版本，实时检测版本可用状态（可用 / 发布后可用 / 不可用）。只选最小版本表示所选版本往后均依赖；只选最大版本表示所选版本往前均依赖；两者都选表示依赖中间范围。
- **合并确认**：`MergeDialogMode2Confirm.vue` 在最终提交前展示所有已解决项的对比摘要。
- **通用详情**：为版本发布管理页各表格的操作列（查看详情/查看）提供统一的详情弹窗，展示完整字段信息。

## 页面导航说明

### 顶部页签
- **版本发布管理**：进入版本管理主页面。
- **业务域设计**：进入业务域建模页面（实体/方法/接口/物理/事件建模）。

### 版本发布管理页
- **概览**：
  - 左侧垂直切换：变更记录 / 外部依赖 / 对外能力 / 基础数据
  - 顶部提供版本下拉切换（带 `最新` / `历史` 标签），数据按选中版本隔离显示
  - 外部依赖 Tab 右下角可"添加依赖"
- **发布记录**：展示 main / bugfix 全局发布历史，右下角可"提交测试"
- **BUG修复**：展示全局 BUG 修复列表，表格上方可切换"交互一/交互二"，点击【合并】打开对应合并弹窗；右下角可"新建 BUG"

### 业务域设计页
页面结构从上至下：
1. **业务域信息栏**：展示域名称+版本、创建时间、分支切换器（main/bugfix）、"管理版本"链接
2. **业务模型切换页签**：医嘱信息 / 草药处方 / 皮试记录 / 检查申请 / 检验申请（可切换、可关闭）
3. **建模子页签**：实体建模 / 方法建模 / 接口建模 / 物理建模 / 事件建模
4. **筛选栏 + 表格 + 分页 + 底部操作栏**

### 操作列弹窗
版本发布管理页内所有表格的操作列已统一接入详情弹窗：
- 变更记录、外部依赖、对外能力、基础数据 → "查看详情"
- 发布记录 → "查看详情"
- BUG修复 → "查看"（查看 BUG 详情）、"合并"（打开合并弹窗）

## 合并流程演示

1. **进入 BUG 修复**：在"版本发布管理 → BUG 修复"列表中，找到状态为"研发完成"的记录，点击【合并】。
2. **选择交互模式**：表格上方可切换交互一/交互二。
3. **交互一（结构化对比）**：
   - 顶部展示分支流向与未解决冲突数。
   - 左侧 `DiffTree` 列出所有变更节点，冲突节点以红色标识。
   - 中右两栏展示该节点在 Hotfix 和 Main 中的业务卡片，并带变更着色（绿=新增、黄=修改、红=删除）。
   - 点击冲突节点，底部出现裁决区，逐条选择合并策略。
4. **交互二（表单三栏对比）**：
   - 左侧列出所有变更的实体/方法对象。
   - 右侧三栏分别展示 Hotfix / Base / Main 的 `EntityEditor` / `MethodEditor`。
   - 变更字段高亮显示，点击高亮单元格，底部固定面板展示三方值并提供"采纳"按钮。
   - 所有冲突解决后，底部【确认合并】按钮可用。
5. **确认合并**：点击后生成最终 JSON 并提示成功（结果输出至控制台）。

## 设计要点

- **算法层**：`diff3.ts` 实现了递归 JSON 对比，对数组采用 `id` 匹配策略，保证实体/字段顺序变化时仍能正确比对。支持 `unchanged` / `auto` / `conflict` 三种合并类型。
- **表现层**：`BusinessNodeCard` 根据 JSON 结构自动推断节点类型（`entity` / `field` / `process`），用中文业务标签替代技术字段名；`EntityEditor` / `MethodEditor` 将技术字段渲染为可读的表格单元格。
- **状态层**：`DiffNode` 上直接绑定 `resolution` 和 `resolvedValue`，利用 Vue3 响应式实现选择即更新、冲突数实时计算。
- **布局层**：主页面采用"顶部 Header + 左侧全局导航 + 左侧树面板 + 右侧详情面板"的经典 B 端布局。版本发布管理页已移除左侧版本列表，改为在概览内通过下拉框切换版本。业务域设计页新增业务模型切换页签栏，层级关系更清晰。所有表格去除了斑马纹以提升通透感，使用清晰边框与纯白背景增强可读性。
