# 权限组件原型需求清单

## 一、项目背景

### 1.1 产品定位
在天宫低码编排平台中，权限组件是**逻辑组件**之一，用于在业务方法/接口的执行链路中插入权限校验节点。该组件直接消费权限中心已定义的权限结果及对外能力。

### 1.2 核心场景
**门诊开药时的处方权校验**
- 医生为患者开具药品医嘱时，系统需在"医嘱保存"接口执行前，校验该医生是否具备开具该类药品的处方权限（西药、中成药、中草药）。
- 若校验通过，继续执行保存；若校验不通过，中断流程并给出提示（如"没有处方权限，无法开具该药品"）。

### 1.3 用户角色
- **配置人员**：信息科工程师/低码平台使用者，负责在编排链路中配置权限节点的具体参数。

## 二、功能需求

### 2.1 整体页面布局
页面采用服务编排经典**三栏布局**：

| 区域 | 需求描述 |
|------|----------|
| **左侧组件面板** | 分类展示逻辑组件、数据库组件、通用组件。权限组件归入"通用组件"。 |
| **中间编排画布** | 以垂直固定链路展示节点：开始 → 权限校验 → 医嘱保存接口 → 结束。节点间用箭头连线。**无需实现拖拽**，链路固定显示即可。点击节点可激活右侧抽屉。 |
| **右侧属性抽屉** | 点击链路中的"权限校验"节点后，右侧滑出抽屉式配置面板，顶部包含 Tab：属性 / 配置引导 / 上下文 / 结构树。 |

### 2.2 权限组件配置框（属性 Tab）

#### 2.2.1 基础信息
- 组件名称：输入框，可编辑。
- 组件备注：文本域，可编辑。

#### 2.2.2 权限选择
- **选择权限**：下拉选择框，从权限中心定义的权限列表中选择（如处方权限 PRES_PER、抗菌药权限 ANTIBIOTIC_PER）。
- 选中后只读展示：权限代码、权限名称。

#### 2.2.3 授权对象配置
- **授权对象类型**：单选，可选值：
  - **系统用户（SYS_USER）**：默认选中。
    - 子选项：当前用户（默认）/ 指定用户。
    - 若选择"指定用户"，需从上下文参数下拉列表中选择具体的用户 ID 参数。
  - **系统角色（SYS_ROLE）**：
    - 可选择从上下文参数下拉列表中指定角色参数（非必填）。
- 提示说明：系统用户默认自动取当前登录用户 ID，由鉴权服务自动传入，无需配置。

#### 2.2.4 字段映射配置（资源对象）
- **核心需求**：配置权限定义中的**资源对象字段**与当前方法/接口**实际业务字段**的映射关系。
- **展示方式**：双列表格，左侧为"资源对象字段（权限定义）"，右侧为"实际业务字段（当前上下文）"，中间用箭头连接。
- **交互**：右侧每行提供"选择上下文字段"按钮，点击后打开右侧弹窗（抽屉），在弹窗中按分类（入参/上下文变量）浏览并选择上下文参数。已选择后显示参数中文名，可点击"更换"重新选择。
- 系统根据映射关系提取业务字段值，与权限分发结果进行比对。

#### 2.2.5 限定条件（可选）
- **条件类型**：下拉选择，可选值：医疗组 / 院区 / 科室 / 机构。
- **上下文参数**：可搜索下拉框，选择对应上下文参数（如 `currentUser.medicalGroupId`、`currentUser.districtId`）。
- 不配置时默认全局生效。

#### 2.2.6 结果处理
- **校验通过**：固定选项"继续执行后续节点"。
- **校验不通过**：
  - 处理方式：流程中断并提示 / 继续执行（记录日志）。
  - 当选择"流程中断并提示"时：
    - **提示语**：必须从预设提示语下拉列表中选择，不支持自定义。
    - **错误码**：只读展示（如 `PERMISSION_DENIED`）。

#### 2.2.7 调用示例
- 根据当前配置动态生成 `checkPermission` 调用示例代码，帮助用户理解最终执行逻辑。

### 2.3 配置引导页签

#### 2.3.1 引导形式
- 采用**垂直步骤条**，共 7 步，步骤标题与属性面板折叠区域保持一致：
  1. 理解权限校验原理（引导特有，属性面板无对应区域）
  2. 权限选择
  3. 授权对象配置
  4. 字段映射配置（资源对象）
  5. 限定条件（可选）
  6. 结果处理
  7. 保存配置（引导特有）

#### 2.3.2 原理可视化
- 第 1 步使用卡片+箭头形式可视化解释："权限中心已定义（资源分发）→ 服务编排要比对（业务数据提取）"。

#### 2.3.3 动态示例
- 第 4 步根据当前选中的权限，动态展示对应的字段映射可视化示例：
  - 处方权限（PRES_PER）→ `request.drugList[*].subjectClassCode`
  - 抗菌药权限（ANTIBIOTIC_PER）→ `request.drugList[*].antiLevel`
  - 病历编辑权（EMR_MODIFY_PER）→ `request.emrList[*].deptId` / `request.emrList[*].medicalGroupId`

#### 2.3.4 状态标签
- 每一步根据实际配置状态动态显示标签：已完成（success）/ 待配置（warning）/ 可选（info plain）。

#### 2.3.5 快捷跳转
- 每一步提供"去配置"按钮，点击后自动切换到"属性"Tab 并展开对应的折叠面板。
- 结果处理对应折叠面板 `name="7"`（跳过只读的鉴权策略 `name="6"`）。

#### 2.3.6 配置检查清单
- 页面底部展示实时检查清单：
  - [ ] 已选择权限
  - [ ] 已配置授权对象
  - [ ] 已配置字段映射
  - [ ] 已设置结果处理
- 已完成的项自动变绿并显示勾选图标，未完成项显示灰色圆圈。

### 2.4 上下文页签
- 以表格形式展示当前链路可用的上下文变量列表。
- 表格列：参数名称、参数编码、类型、说明。
- 列宽自适应，支持文字溢出 Tooltip。

### 2.5 结构树页签
- 以 JSON 格式化预览当前权限组件的完整配置数据结构。

## 三、交互需求

### 3.1 节点选中态
- 点击中间链路中的权限组件节点，节点边框高亮（蓝色阴影），右侧抽屉展开。
- 点击其他节点（如开始、结束、业务方法），右侧抽屉展示对应的基础信息。

### 3.2 表单联动
- **权限切换联动**：切换不同权限时，自动清空并回填该权限对应的默认字段映射值和默认提示语。
- **授权对象类型切换联动**：切换系统用户/系统角色时，自动重置对应的子选项状态。
- **Tab 切换**：属性 / 配置引导 / 上下文 / 结构树四个 Tab 可自由切换，切换时保留当前配置状态。

### 3.3 上下文参数选择交互
- 所有上下文参数选择框统一使用可搜索下拉框（`el-select-v2` 或等效组件）。
- **显示规则**：下拉列表默认展示参数的中文名称（`label`）。
- **Tooltip 规则**：鼠标悬停在选项上时，通过 Tooltip 显示参数编码路径（`value`）。
- 支持允许用户手动输入不在列表中的参数路径（`allow-create`）。

### 3.4 抽屉收起/展开
- 抽屉右上角提供收起按钮（`>>` 图标），点击后抽屉宽度收缩为 0。
- 再次点击或选中节点后自动展开。

## 四、数据需求

### 4.1 权限列表数据（Mock）
每条权限定义需包含：
- `code`：权限代码（如 PRES_PER）
- `name`：权限名称（如处方权限）
- `desc`：权限描述
- `resourceFields`：资源对象字段数组，每项包含 `code`、`name`、`objectName`、`fieldName`
- `authStrategy`：鉴权策略文本数组，每项包含 `text`、可选 `logic`

### 4.2 上下文变量数据（Mock）
每条上下文变量需包含：
- `paramName`：参数中文名称（如药品科目类别）
- `paramCode`：参数编码路径（如 `request.drugList[*].subjectClassCode`）
- `type`：数据类型（array / string / object 等）
- `desc`：说明
- `category`：分类（如 入参 / 上下文变量）

### 4.3 提示语数据（Mock）
- 提供预设提示语列表，每项包含 `code` 和 `text`。
- 错误码固定只读：`PERMISSION_DENIED`。

### 4.4 默认示例配置
页面首次加载时，默认选中"处方权限（PRES_PER）"，并预填充以下示例值：
- 组件名称：权限校验：处方权限
- 授权对象：系统用户 - 当前用户
- 字段映射：处方科目类别 → `request.drugList[*].subjectClassCode`
- 结果处理：校验不通过时中断，提示语"没有处方权限，无法开具该药品"

## 五、非功能需求

### 5.1 技术栈
- **Vue 3（CDN）**：响应式框架
- **Element Plus（CDN）**：企业级 UI 组件库
- **Element Plus Icons（CDN）**：图标库
- **纯静态 HTML**：无需构建工具（Vite/Webpack），单 HTML 文件即可运行

### 5.2 兼容性
- 支持 Chrome、Edge、Firefox 等现代浏览器。
- 支持本机直接打开（`file://` 协议）或通过本地 HTTP 服务器访问（推荐）。

### 5.3 性能
- 页面为静态原型，无后端接口调用，无大数据量渲染，要求首屏加载流畅。

### 5.4 可访问性
- 关键操作按钮需有明显的颜色区分（主操作蓝色、成功绿色、警告黄色）。
- 表单必填项需有红色星号标识。
- 只读字段需有明显的禁用态样式。
