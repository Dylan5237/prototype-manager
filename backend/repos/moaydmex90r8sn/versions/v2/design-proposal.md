# 权限组件设计思路

## 一、核心概念梳理

### 1.1 权限的本质
权限的本质是**"分发结果"与"实际业务数据"的比对**。以门诊处方权为例：

1. **权限中心已定义**：把"药品科目类别"（西药/中成药/中草药）分发给医生
2. **服务编排要比对**：当前医嘱里的药品是什么类别
3. **比对逻辑**：药品类别 包含于 医生的处方权限分发结果

### 1.2 关键名词
| 名词 | 说明 |
|------|------|
| **资源对象** | 权限定义中的校验字段（如"处方科目类别"） |
| **授权对象** | 谁拥有这个权限（系统用户/系统角色） |
| **字段映射** | 资源对象字段 → 当前方法/接口的实际业务字段的对应关系 |
| **限定条件** | 权限生效的特定范围（如某医疗组、某院区） |

## 二、用户故事

**作为** 信息科工程师/低码平台配置人员
**我希望** 在编排链路中配置一个权限校验节点
**以便** 在业务方法执行前自动校验当前用户是否具备相应权限

**场景**：
- 医生为患者开具药品医嘱时，系统需在"医嘱保存"接口执行前，校验该医生是否具备开具该类药品的处方权限
- 若校验通过，继续执行保存
- 若校验不通过，中断流程并给出提示（如"没有处方权限，无法开具该药品"）

```
开始
  ↓
权限校验
  ↓
医嘱保存接口
  ↓
结束
```

### 3.3 右侧抽屉 Tab
- **属性**：基础信息 / 权限选择 / 授权对象配置 / 字段映射配置 / 限定条件 / 结果处理 / 调用示例
- **配置引导**：7步垂直步骤条 + 实时检查清单
- **上下文**：上下文变量表格
- **结构树**：JSON 格式化预览

## 四、配置逻辑设计

### 4.1 权限选择
- 从权限中心定义的权限列表中选择（Mock：处方权限 PRES_PER、抗菌药权限 ANTIBIOTIC_PER、病历编辑权 EMR_MODIFY_PER）
- 选中后只读展示：权限代码、权限名称

### 4.2 授权对象配置
- **系统用户**：默认取当前登录用户，也可指定上下文中的用户 ID 参数
- **系统角色**：需指定角色参数（从上下文中选择）

### 4.3 字段映射配置（核心）
配置**资源对象（权限定义中的校验字段）**与**当前方法/接口的实际业务字段**的映射关系。

系统提取实际业务字段的值，与权限分发结果进行比对。

**示例**：
- 处方权限（PRES_PER）→ `request.drugList[*].subjectClassCode`
- 抗菌药权限（ANTIBIOTIC_PER）→ `request.drugList[*].antiLevel`
- 病历编辑权（EMR_MODIFY_PER）→ `request.emrList[*].deptId` / `request.emrList[*].medicalGroupId`

### 4.4 限定条件（可选）
如需在特定范围（如医疗组、院区）内校验权限，可指定上下文参数作为限定条件。

### 4.5 结果处理
- **校验通过**：继续执行后续节点
- **校验不通过**：流程中断并提示 / 继续执行（记录日志）

## 五、技术选型

- **Vue 3（CDN）**：响应式框架，单文件无需构建
- **Element Plus（CDN）**：企业级 UI 组件库
- **Element Plus Icons（CDN）**：图标库
- **纯静态 HTML**：无需 Vite/Webpack，直接浏览器打开即可运行
